## TIR与AvgExec的准确计算边界

- AvgExec = 各选中任务全部实际测试调用次数之和 / 选中任务总数。跨R1/R2/R3、失败和重试都累计；普通执行、独立覆盖和变异中的真实测试调用计入，同一次执行兼采覆盖只计一次；解析、编译、仅收集不计次数。需要任务/会话/调用唯一标识、用途、是否真的启动测试，以及完整记录的标识。不能以 iterations、reports数量、attempt_count、运行时间或PIT变异体数代替。
- TIR = 确认改善的目标数 / 具有可比较证据且实际采取行动的目标数 ×100%。按任务/轮次/步/预先目标标识去重，使用独立判定的行动前状态与实际保留后状态；被拒绝候选的改善不直接算最终改善，预检查恢复按相同口径计入。完整记录确实没有可比较目标时才是N/A。
- 旧test_intent_plans保存的是focus、gaps、target_states等规划信息，不是本文所需的逐目标预注册及独立前后判定账本。旧报告也没有覆盖全部测试调用的计数账本。因此14个批次的两项指标均无法据现有数据准确填写；“—”表示缺证，不是0。
- 现有两个完整方法结果目录不能代替w/o State Update、w/o History Comparison、w/o TSG等独立对照实验。对应表格不补造结果。
- 此次只修改展示及历史结果核对逻辑，没有为未来运行新增全链路计数或逐目标判定记录；未来若要获得这两项精确指标，仍须单独接入上述记录机制。

## 模型及论文差异

- runs-DeepSeek-R1 的7份批量摘要、711份任务摘要均记录 deepseek-r1:14b。
- runs-GPT-4 的7份批量摘要、711份任务摘要均记录 gpt-oss:20b，不是标称GPT-4。这里描述的是日志记录，不证明服务器真实加载了何种权重。论文原有模型标签暂不擅自改写。
- 例如DeepSeek TestEval按当前batch_summary计算PassRate为99.5238%，论文现填93.81%；Commons-Cli核对值26.4706%，论文现填66.47%。因此不能认定现有表格全部由这两组结果按同一口径产生。应先明确实验版本和统计口径，不能机械覆盖。
- 两个目录未发现内容逐字节相同的任务摘要（不据此推断测试代码完全不同或没有历史复用）。

## 可复查方式

在项目目录运行：

```powershell
python scripts/audit_experiment_metrics.py ../runs-DeepSeek-R1 ../runs-GPT-4
```

脚本只读文件并向终端输出JSON：包括模型、计数、规划字段、摘要字段及跨目录相同摘要记录。TIR/AvgExec在本历史审计中固定标记为缺少证据；它不是未来实验的通用指标计算器。
